Chapter 3: Declarative JSON

The Joy of Declarative JSON

Separating intent from execution: why JSON instructions make UI code readable, testable, and unbreakable.

Separating Intent from Execution

In traditional scripts, the question of "What should happen when this button is clicked?" is tangled together with the plumbing of DOM querying and listener attachment.

By moving the binding configuration into a serializable JSON file (bindings.json), your entire event architecture becomes a clear contract: 

[
  {
    "event": "click",
    "selector": "#rakaBtn",
    "narration": "Load and populate Raka columns JSON into editor"
  },
  {
    "event": "click",
    "selector": "#templateBtn",
    "narration": "Load and populate template JSON into editor"
  },
  {
    "event": "click",
    "selector": "#buildBtn",
    "narration": "Transform columns with template and show in output tab"
  }
]

Why Plain Data Wins

Human-Readable

Anyone on your team can read bindings.json like documentation and know all interactive UI actions in 30 seconds.

Pre-Flight Guarding

Before attaching listeners, you can validate the JSON: verify that DOM selectors exist and actions are defined, catching errors before users ever click.

Zero Folder Clutter

Adding a 4th button doesn't require a new folder or new addEventListener boilerplate. You just add one object to the array.
