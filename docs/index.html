The Strict Boundary (v2 Revision)

A common trap in frontend design is conflating event wiring with DOM manipulation or data extraction.

The Golden Separation:
  • dom-primitive-bindings (This Repo): The Wiring Layer. It attaches one listener per event type to the container, resolves the bubbling target via closest(selector), and hands over { event, targetElement }. It never alters DOM elements and never extracts business schemas.
  • dom-primitive-engine (Sibling Repo): The Extraction Layer. Once an event is intercepted, it executes declarative instruction pipelines (e.g. closest("tr"), querySelectorAll("td"), mapping values) to extract pure JSON.

By keeping dom-primitive-bindings 100% focused on delegation, it remains ultra-lightweight (~2 kB), unbreakable, and completely agnostic to what your application does with the event.

Staged Architecture in src/v2/

1. guards/

Validates inputs before any listener registration. Separated into container/ (validates first input) and bindings/ (validates second input array).

2. prepare/

Groups bindings by event type into a Map<eventType, bindings[]>, ensuring exactly one listener per event type is attached to the container.

3. listeners/

Attaches container event listeners that intercept bubbling browser events and forward them into the dispatch pipeline.

4. dispatch/

Matches targets via closest(selector), passes { event, matchElement } to the runner, and emits results to onExtract.

Browser Usage via window.ks

Include the bundled distribution or ES module, then call bindEvents: 

<script type="module" src="/docs/dist/v2/min.js"></script>
<script type="module">
  const bindings = [
    {
      event: "click",
      selector: ".btn-show",
      runner: (target, instructions, clientData) => {
        console.log("Delegated click captured on:", target);
        return { targetTag: target.tagName, eventType: clientData.event.type };
      },
      onExtract: (data) => console.log("Binding executed:", data)
    }
  ];

  window.ks.domPrimitiveBindings.bindEvents("container-id", bindings);
</script>

Code Conventions

  • Every folder has an index.js file acting as its public gateway.
  • Single-function default export per file (no default export objects).
  • Zero comments in code: Folders and file names tell the story directly.
  • Pure delegation: Zero DOM manipulation and zero schema parsing inside this engine.
