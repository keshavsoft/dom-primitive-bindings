The Staged Pipeline Architecture

How src/v3 turns complex delegation into 4 crystal-clear decoupled stages.

Inside the src/v3/ Pipeline

Rather than writing a monolithic event listener, dom-primitive-bindings breaks the work into 4 decoupled stages where every folder contains an index.js and exports a single function:

Stage 1
guards/

Validates and resolves inputs before touching the DOM:
• container/: Resolves container ID or DOM node.
• bindings/: Validates that bindings is a valid array of items with event and selector.

Stage 2
prepare/

Groups all bindings by event type into a Map<eventType, bindings[]>. If you have 10 click bindings, it ensures only one click listener is attached to the container.

Stage 3
listeners/

Attaches the container event listeners. Each listener intercepts the native bubbling event and invokes the dispatch pipeline.

Stage 4
dispatch/

Matches target elements via event.target.closest(binding.selector), resolves inputs (keyboard vs click element), and passes { event, matchElement } to the runner.

The Orchestrator (src/v3/index.js) 

const bindEvents = (containerOrId, bindings = []) => {
  // 1. Validate inputs
  const guarded = runGuards(containerOrId, bindings);
  if (!guarded) return null;

  // 2. Group bindings by event type
  const { container, bindings: validBindings } = guarded;
  const eventGroups = prepareBindings(validBindings);

  // 3. Attach container listeners (delegating to dispatch)
  attachListeners(container, eventGroups);

  return container;
};
